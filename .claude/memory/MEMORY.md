- [Voice MCP playback](feedback_voice_mcp_playback.md) — synthesize + pipe is ONE atomic pair; always run the "Recommended playback" Bash from the response in the SAME turn as the synthesize call.
- [Voice chunks ≤20s](feedback_voice_chunks.md) — split voice responses longer than ~20s / 55 words into multiple back-to-back synthesize+pipe pairs at sentence boundaries.
- [Always delegate](feedback_always_delegate.md) — non-trivial implementation work goes to an Agent subagent; main context is for orchestration only.
- [Voice first](feedback_voice_first_response.md) — every response opens with a short voice call (≤1 paragraph), then the detailed text.
- [Voice carries content](feedback_voice_carries_content.md) — the voice call MUST carry the substantive findings/report, not a generic "checking now" placeholder. Final answer goes in the voice, not just the text.
- [Parallel agents](feedback_parallel_agents.md) — dispatch independent agents in a single message so they run concurrently.
- [Command + settings registry required](feedback_command_registry_required.md) — every new editor action registers via registerCommand; every new setting via registerSetting (apps/editor/src/state/use{Command,Settings}Store.ts). Include the verbatim directive in every agent brief that touches editor UI.
- [Playwright screenshots → screenshots/](feedback_playwright_screenshots_folder.md) — every browser_take_screenshot call must set `filename:` under `screenshots/` (the folder is already gitignored). Default cwd output leaks PNGs into the repo root.
- [Dispatch without approval gate](feedback_dispatch_without_approval_gate.md) — when the next step is clear, dispatch the agent immediately. Don't pause to ask "say go" or have the user approve briefs/panel picks — they redirect mid-flight if they disagree.
- [Panel responsive design + scroll-on-hover](feedback_panel_responsive_design.md) — every scene-panel build must be heavily responsive (dockview panels render at unpredictable sizes). Vertical scrollbars OK (already themed); horizontal scroll uses the `TabStrip scrollable` hover-area pattern, never a native horizontal scrollbar.
- [Progressive tooltips everywhere](feedback_progressive_tooltips.md) — project-wide hover standard. 2s shows short label, 5s shows label + full description, via `<Tooltip stages={...}>`. Apply to page tabs, dock buttons, action buttons, anywhere context-on-hover helps. Labels + descriptions live on the control's fixture/config so wraps are consistent.
- [Agent dev-server ports](feedback_agent_dev_server_ports.md) — assign each worktree agent a distinct unused port (3010-3099 range). Don't let agents and orchestrator collide on default 3001.
- [Agent Playwright contention](feedback_agent_playwright_contention.md) — agents using Playwright MUST open their own tab via `browser_tabs new` and operate on it; don't share the orchestrator's default tab.
- [Wave merge gate](feedback_wave_merge_gate.md) — never dispatch a new wave until the previous one is merged to main, typechecks clean, and is pushed. Hard gate, no exceptions.
- [No worktrees](feedback_no_worktrees.md) — stop using `isolation: "worktree"`. Shared `.git/` caused WSL VHDX corruption + cwd race. Serialize overlapping work in main checkout instead.
- [No horizontal scroll for categories](feedback_no_horizontal_scroll_for_categories.md) — primary navigation chip strips never scroll horizontally. Wrap to 2 rows, or fall back to icon-only chips. `<ScrollRow>` is only for content overflow, not category/filter UI.
- [TTS the question](feedback_tts_questions.md) — every `AskUserQuestion` MUST be paired with a `mcp__voice__synthesize` carrying the actual question + recommendation. User often isn't at the screen.
- [Raycaster: billboard sprites](project_raycaster_billboard_prefabs.md) — Cardboard is a Wolfenstein-style raycaster. Prefabs are billboard sprites (2D quads facing camera), NOT 3D meshes. EntityPreviewPanel's current cubes are wrong — needs billboard quad fix.
- [Page layouts + shared docks](feedback_page_layouts_and_shared_docks.md) — every page build adds predefined layouts, page-specific opt-in panels, and shared panels (Output/Problems/Notes/History/Assets) registered project-wide.
- [Popout state sync](feedback_popout_state_sync.md) — Wave 3 wiring MUST work when panels are popped out into separate windows. Use persist + storage events for durable state, BroadcastChannel for ephemeral. Design the sync layer BEFORE building stores.
- [Text for remote sessions](feedback_text_for_remote_sessions.md) — voice plays on desktop only; phone sees text. Every voice call needs an accompanying text response carrying the same substantive content.
- [Audit-then-fix loop](feedback_audit_then_fix_loop.md) — per-panel polish goes through a 2-agent loop: AUDIT agent reports findings, FIX agent acts on them. Orchestrator writes both briefs, reviews findings between, enforces high standards.
- [DnD is day one](project_dnd_day_one.md) — cross-window drag-and-drop is foundational infrastructure. Must be designed + scaffolded BEFORE Wave 3.3 panel migrations so panels are DnD-aware from the start. Plan lives at `docs/plans/CROSS_WINDOW_DND.md`.
- [IDB is source of truth](project_idb_source_of_truth.md) — IndexedDB holds project data; pack export and playtest both read from IDB. Asset/content stores are reactive views over `EditorProjectStore` + `IdbAssetPack`, NOT LS-persisted Zustand. LS-backed sync is for UI state only.
- [Prefabs are declarative assets](project_prefabs_declarative_assets.md) — each prefab is a JSON file declared in the pack manifest like textures/scripts/sounds. Runtime modAPI is READ + spawn only (`api.prefabs.get/.spawn`), NOT register. Any `registerPrefab` in current modAPI is vestigial OR a dynamic escape hatch that needs rename — flagged for doc audit.
